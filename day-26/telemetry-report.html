Honest limitation, not hidden: the −6101 ms row isn't a bug in the data — ProcessOutboxMessage (11.75s) runs after the request already returned (5.68s), so naive requestDuration − dependencyDuration goes negative for this async continuation. Every synchronous row above is sane. The query needs a time-window guard to handle background work correctly — flagged, not silently patched.
